--- title: Remote control, headless runs and scripting description: Drive the open MaveScape window from scripts on your computer with --remote-control, score a table with its design without a window (mavescape run), and check them before scoring (mavescape validate). lede: Started with --remote-control, MaveScape accepts actions from programs on your computer: open an example or your files, score, read the quality control, select variants, export. Each action happens in the open window, where you see it; its changes go into the history and can be undone. For pipelines, mavescape run does a whole analysis without a window, and mavescape validate checks the files first. ---

Turn it on

$ mavescape --remote-control

MaveScape prints the address actions go to and the token that reading and writing files need, and writes both to remote.json in its data folder, readable only by you (~/Library/Application Support/MaveScape/remote.json on macOS), so scripts can find a running MaveScape without being told. The file is removed when MaveScape stops.

{
  "url": "http://127.0.0.1:8820",
  "token": "…",
  "version": "{{version}}",
  "pid": 41237
}

Only programs on this computer can use remote control, addressing it as 127.0.0.1 or localhost, and web pages on other sites cannot. A MaveScape started with --remote-control while another is running starts on the next free port rather than handing its files over, so the script reaches a window it can drive.

Sending an action

POST {"action": …, "args": {…}} to /api/remote/action. The answer is {"ok", "message", "data"}: the message in words, the data for scripts.

$ curl -s http://127.0.0.1:8820/api/remote/action -d '{"action": "open_example", "args": {"id": "grb2-sh3"}}'
$ curl -s http://127.0.0.1:8820/api/remote/action -d '{"action": "qc_findings"}'

Names are forgiving: "grb2" finds the GRB2 example, "Run 2" or "2" a run, W36A the variant p.Trp36Ala. A wrong name is answered with the choices. Actions run one at a time, in the most recently opened window; GET /api/remote/tools lists every action with its arguments as JSON Schema.

ActionWhat it does
get_stateThe workspace: tables, targets, design, runs, selections, the view, and the analysis steps with the next one
new_workspaceStarts a new workspace (name)
open_exampleOpens an example, scored (id)
open_filesOpens files by path, importing tables with the mapping MaveScape detects (paths, new_workspace; review leaves the import wizard open). Needs the token
set_modeShows a view: start, experiment, qc, score or map
focusShows a table, target, run, selection or variant in the inspector
draft_designDrafts the design from the column names and reports its problems
set_designSets a mavescape-design document, refused with every problem when it does not fit the table
checkChecks a table as scoring would, without scoring: its names against the design's target, the design against its columns, the parameters against the design; says what blocks scoring (design, preset, parameters)
reproduce_runRecomputes a saved run from its recorded inputs and checks its output hash; refused, saying why, when it differs
scoreScores with a preset (mavescape, enrich2 or dimsum, which returns each replicate's fitted scale, shift and error terms) and changed parameters, such as {"model": "ratio"} for a time series by its ends, {"model": "bins-mle"} for sorted bins by maximum likelihood or {"differential": "paired"} to compare conditions by pairs of replicates; with conditions compared, how many variants differ; the existing run when the inputs are the same
qc_findingsEach finding of a run (or of the counts) with its status, value, threshold and rationale; finding shows one in the QC view
select_variantsSelects variants or positions on the map, optionally only those scored, low, filtered or missing, and saves the selection (save_as)
inspect_variantA variant's score, SE and interval, flags, replicates and counts (for a regression, each replicate's time points and departure from a line; with conditions compared, each difference with its SE, interval and q)
render_mapShows the map with the given coloring (differential for a comparison of conditions, and contrast to choose one), row order, palette and zoom, and returns it in words
exportWrites scores, counts, qc-samples, qc-variants, barcodes (a table of barcodes), differential (conditions compared), provenance, methods, references, map (SVG), selection or archive to path. Needs the token

Reading and writing files

open_files and export need the header X-MaveScape-Token with the token from remote.json: another user of a shared computer can reach the loopback port, but not your files. Exports take an absolute path whose folder exists, and never replace a file unless the call says "overwrite": true. The file is written through a temporary file renamed into place, so a reader never sees half of it.

$ TOKEN=$(python3 -c 'import json, os; print(json.load(open(os.path.expanduser("~/Library/Application Support/MaveScape/remote.json")))["token"])')
$ curl -s http://127.0.0.1:8820/api/remote/action -H "X-MaveScape-Token: $TOKEN" -d '{"action": "export", "args": {"what": "scores", "path": "/tmp/grb2_scores.csv"}}'

From Python

No client library is needed; the standard library is enough:

import json, os, urllib.request

connection = json.load(open(os.path.expanduser("~/Library/Application Support/MaveScape/remote.json")))

def act(action, **args):
    request = urllib.request.Request(
        connection["url"] + "/api/remote/action",
        data=json.dumps({"action": action, "args": args, "client": "my notebook"}).encode(),
        headers={"Content-Type": "application/json", "X-MaveScape-Token": connection["token"]},
    )
    answer = json.load(urllib.request.urlopen(request))
    if not answer["ok"]:
        raise RuntimeError(answer["message"])
    return answer

act("open_files", paths=["/data/counts.csv", "/data/target.fasta"], new_workspace=True)
act("draft_design")
run = act("score")["data"]
findings = act("qc_findings")["data"]["findings"]
print(run["name"], [(f["title"], f["status"]) for f in findings])
act("export", what="scores", path="/data/scores.csv")

On Linux the data folder is ~/.config/MaveScape, on Windows %AppData%\MaveScape, unless MaveScape was started with --data-dir. The client name appears in the window's log beside each action.

Headless runs

mavescape run scores a count table with its design without a window, for pipelines and continuous integration. It starts MaveScape on a private port with a temporary library, opens it in a headless Chrome (or Chromium, Edge or Brave: --chrome, or the CHROME variable), performs the analysis through the actions above, writes the files to a folder and stops.

$ mavescape run --design design.json --out results/ counts.csv
MaveScape {{version}}: running in Google Chrome
[1] new_workspace: ok (0.0 s) Started a new workspace, "GRB2 SH3 domain, Domainome abundance (aPCA)".
[2] open_files: ok (0.1 s) Opened the table counts.csv.
[3] set_design: ok (0.0 s) Set the design of counts.csv: two-population, 3 replicates.
[4] check: ok (0.0 s) Valid: counts.csv, 1121 rows (1121 names valid), with the design (two-population, 3 replicates of 6 samples).
[5] score: ok (0.1 s) Run 1: 1118 of 1121 variants scored (MaveScape defaults).
[6] qc_findings: ok (0.1 s) Quality control of Run 1: 1 fail, 0 to review, 11 pass.
[7] export: ok (0.0 s) Wrote results/scores.csv (341969 bytes).
…
Done in 1.2 s: 9 files written to results (run.json lists them).

It checks first: the table's variant names against the design's target, the design against the table's columns, and the parameters against the design. When anything blocks scoring it scores nothing. Then it scores, with MaveScape's defaults or --preset enrich2, dimsum or vampseq, and --parameters params.json for the parameters to change (as the score action takes them). It runs the quality control and writes the run's files. A table of barcodes is named with its barcode-to-variant map (counts.csv map.csv); a target not in the design is given with --target.

FileWhat it holds
scores.csvThe scores in MaveDB's columns; with several conditions, scores_<condition>.csv for each
counts.csv, qc_samples.csv, qc_variants.csvThe counts scored, and quality control per sample and per variant
differential.csv, barcodes.csvWith conditions compared, the differential scores; for a table of barcodes, each barcode
map.svgThe variant-effect map (protein-level variants)
provenance.json, methods.md, references.bibThe record and the methods paragraph with its references
workspace.mszThe analysis as a workspace archive, to open in the window or run again
run.jsonThe command, the inputs and every output with their SHA-256, each step with its outcome and time, the run's id and output hash, and its QC (FORMATS.md)

The same bytes again. The scores, counts, QC, map, methods and references are the same bytes for the same inputs. The provenance and the workspace archive also record when they were made: give --time 2026-10-09T12:00:00Z, or set SOURCE_DATE_EPOCH, and every record carries that time, so every file is the same bytes. --from-workspace analysis.msz (with --run "Run 2", else the latest) reruns a saved run. Its scores are recomputed from its recorded table, design and parameters and must have its recorded output hash; otherwise the run stops.

Exit status: 0 when done. 1 when the run was not done or found a blocking problem: a design that does not fit the table, parameters that cannot score, a run that did not reproduce, a QC finding that blocks (a sample with no counts), or with --strict any failing finding (the files are still written). 2 for a wrong command line, a missing input, an output folder that is not empty (unless --overwrite), or no browser. run.json says why. --log json prints the progress as one JSON object per line, for a pipeline's logs.

Checking before scoring

$ mavescape validate --design design.json counts.csv
Valid: counts.csv, 1121 rows (1121 names valid), with the design (two-population, 3 replicates of 6 samples).

mavescape validate checks tables, a design and parameters as scoring would, without scoring, and lists what blocks scoring and the warnings. It exits 0 when they are valid and 1 when not; --json prints the report as JSON. A design alone is checked without its table, and a score table against its target (--target).
