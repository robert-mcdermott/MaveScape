Methods, validation and citation

MaveScape reimplements published methods for scoring deep mutational scans. This page shows how its results are checked against the tools those methods come from and against experiments whose answers are known, how to cite it, and whose work it builds on.

Validation

Unit tests check each function against hand-computed and published values. The validation suite runs the complete pipelines, the way they run in the app, and reports how closely MaveScape agrees with the reference, against a stated tolerance. It runs in continuous integration on every change, with the public data it needs fetched and checked against their SHA-256 checksums.

The data are three MaveDB records under CC0, chosen to differ: GRB2's SH3 domain from the Human Domainome (two populations, three replicates), BRCA1's RING domain (a time series with shared inputs and a second assay in the same table), and factor IX (sorted bins over overlapping tiles). validation/README.md lists every check and how the reference outputs were made.

The same bits in every browser

JavaScript's Math.log and Math.exp may differ in their last bit between engines, and they do: Chrome 154 and Node 22 disagree on about 2% of logarithms. MaveScape computes its logarithms and exponentials with fdlibm's algorithms written in plain arithmetic, which every engine performs identically, so a run's output hash does not depend on the browser that scored it and a saved run reproduces after a browser update.

Methods it reimplements

MaveScape's scores are reimplementations of published methods. Their authors are cited in the code and in the methods paragraph MaveScape writes for each run:

  • Scores: log ratios of frequencies before and after selection, with normalization to the wild type, as in Enrich2 (Rubin et al., Genome Biology 2017).
  • Replicates: REML random effects (Viechtbauer, J Educ Behav Stat 2005), computed as metafor does (Viechtbauer, J Stat Softw 2010); Enrich2's own estimator; heterogeneity as Q and I² (Higgins and Thompson, Stat Med 2002).
  • Quality control: variance beyond counting read as DiMSum's multiplicative and additive error terms (Faure et al., Genome Biology 2020).
  • Variant names and exports: MAVE-HGVS and MaveDB's columns (Esposito et al., Genome Biology 2019).

Cite MaveScape

If you use MaveScape in published work, please cite it together with the methods its methods paragraph lists for your run. The repository's CITATION.cff holds the citation, and GitHub's Cite this repository button formats it.

McDermott R. MaveScape, version 0.1.0. https://github.com/robert-mcdermott/mavescape

Privacy and security

MaveScape listens on 127.0.0.1 only, refuses requests whose Host header is not this computer and API calls from other web pages, and serves its page with a strict Content-Security-Policy. It makes no network requests of its own. Remote control is off unless MaveScape is started with --remote-control; even then only programs on this computer can use it, and reading or writing files needs a token that only you can read.

What MaveScape is not

MaveScape reports experimental functional effects for research. It does not classify variants as pathogenic or benign, and its scores are not clinical evidence on their own.
